# 1. Introduction to Cybersecurity

Cybersecurity is the practice of protecting computers, servers, networks, applications and data from unauthorized access, misuse, disruption or damage.

There are two major areas of cybersecurity:

## 1.1 Offensive Security

Offensive security involves thinking and acting like an attacker to identify weaknesses in systems before malicious attackers exploit them.

The main objective is to discover vulnerabilities, demonstrate their potential impact and recommend fixes.

Examples:

- Identifying exposed directories on a web server.
- Finding outdated software.
- Testing authentication mechanisms.
- Identifying insecure configurations.
- Performing authorized penetration testing.

## 1.2 Defensive Security

Defensive security focuses on protecting systems, applications, networks and data from cyber threats.

The main objective is to prevent attacks, detect suspicious activity, investigate incidents and reduce damage.

Examples:

- Monitoring security alerts.
- Reviewing firewall and authentication logs.
- Detecting malware.
- Blocking malicious network traffic.
- Investigating suspicious login attempts.
- Isolating compromised systems.

## 1.3 Offensive Security vs. Defensive Security

| Offensive Security                 | Defensive Security                  |
| ---------------------------------- | ----------------------------------- |
| Thinks like an attacker            | Thinks like a defender              |
| Identifies vulnerabilities         | Protects systems against threats    |
| Performs penetration testing       | Performs security monitoring        |
| Simulates attacks                  | Detects and investigates attacks    |
| Commonly associated with Red Teams | Commonly associated with Blue Teams |

**Important:** Security testing must only be performed on systems for which explicit permission has been provided.

## 1.4 DirBuster

DirBuster is a free and open-source web application directory and file discovery tool.

It helps identify hidden directories and files on web servers that may not be directly linked from the website.

It can use:

- Dictionary-based discovery.
- Wordlists.
- Brute-force techniques.
- Different directory and file discovery methods.

Example use cases:

- Discovering directories that are not linked on a website.
- Identifying accidentally exposed resources.
- Checking whether sensitive files are publicly accessible.

A discovered directory is not automatically a vulnerability. Its permissions, contents and security impact must be evaluated.

# 2. Computer Fundamentals

## 2.1 Inside a Computer System

A computer consists of hardware and software.

- **Hardware:** Physical components of a computer.
- **Software:** Instructions and programs that tell the hardware what to do.

### Motherboard

The motherboard is the main circuit board of a computer.

It connects the CPU, RAM, storage devices, GPU and other components so they can communicate.

### CPU — Central Processing Unit

The CPU is the main processor of a computer.

It executes instructions, performs calculations and controls many operations.

Important points:

- The CPU is commonly called the processor.
- Modern CPUs contain multiple cores.
- Each core can execute instructions.
- Multiple cores allow parallel processing.
- The CPU connects to the motherboard through a CPU socket.

### RAM — Random Access Memory

RAM temporarily stores the data and instructions that the CPU needs to access quickly.

Important characteristics:

- RAM is volatile memory.
- Data stored in RAM is normally lost when power is removed.
- More RAM can help a computer run multiple applications simultaneously.
- RAM is significantly faster than traditional storage devices.

### Storage — HDD and SSD

Storage devices retain data even when the computer is switched off.

They store:

- Operating systems.
- Applications.
- Documents.
- Images and videos.
- System files.
- Other user data.

#### HDD — Hard Disk Drive

- Uses magnetic disks to store information.
- Contains moving mechanical parts.
- Generally offers lower cost per storage capacity.
- Can be slower than an SSD.
- Commonly used for large-capacity storage.

#### SSD — Solid State Drive

- Uses flash memory.
- Has no moving mechanical parts.
- Generally provides faster access and transfer speeds than an HDD.
- Commonly used for operating systems and applications.
- Usually costs more per unit of capacity than an HDD.

| HDD                                 | SSD                                 |
| ----------------------------------- | ----------------------------------- |
| Uses magnetic disks                 | Uses flash memory                   |
| Contains moving parts               | No moving parts                     |
| Generally slower                    | Generally faster                    |
| Lower cost per GB in many markets   | Higher cost per GB in many markets  |
| Can be affected by mechanical shock | More resistant to physical movement |

Storage commonly connects through SATA or PCI Express interfaces. Many modern SSDs use NVMe over PCIe.

### Other Important Components

| Component       | Purpose                                                             |
| --------------- | ------------------------------------------------------------------- |
| PSU             | Power Supply Unit; supplies electrical power to computer components |
| GPU             | Graphics Processing Unit; processes graphics and parallel workloads |
| NIC             | Network Interface Card; enables network connectivity                |
| Cooling system  | Removes heat from computer components                               |
| CPU socket      | Provides the physical connection for the CPU                        |
| Expansion slots | Allow additional hardware components to be installed                |

## 2.2 What Happens When We Press the Power Button?

The process of starting a computer is called booting.

### Step 1: Press the Power Button

When the power button is pressed, the system begins powering up.

The Power Supply Unit supplies the required electrical power to the components.

### Step 2: Firmware Starts

The system firmware initializes the hardware.

Two commonly discussed firmware technologies are:

- BIOS — Basic Input/Output System.
- UEFI — Unified Extensible Firmware Interface.

BIOS is the older firmware approach. UEFI is its modern successor.

### Step 3: POST — Power-On Self-Test

POST checks important hardware components during startup.

It checks whether required components are present and functioning sufficiently for the system to continue booting.

### Step 4: Boot Device Selection

The firmware checks its configured boot order to identify a bootable device.

Examples:

- HDD.
- SSD.
- USB drive.
- Network boot device.

### Step 5: Bootloader Starts

The firmware starts the bootloader from the selected boot device.

The bootloader loads the operating-system kernel and required startup components into memory.

### Step 6: Operating System Loads

The operating system takes control of the computer.

It initializes the required drivers, services and system components.

### Step 7: Login Screen or Desktop

After startup is complete, the user can log in and access the operating system.

### Boot Process Summary

```text
Press Power Button
        |
        v
Power Supply Starts
        |
        v
UEFI / BIOS Initializes Hardware
        |
        v
POST
        |
        v
Select Boot Device
        |
        v
Bootloader Starts
        |
        v
Operating System Loads
        |
        v
Login Screen / Desktop
```

## 2.4 Client–Server Basics

The client–server model describes how two systems communicate to provide services.

### Client

A client is a device or application that requests a service or resource.

Examples:

- Web browser.
- Email application.
- Mobile application.

### Server

A server is a system that provides services or resources to clients.

Examples:

- Web server.
- Database server.
- File server.
- Mail server.

### Request and Response

Communication between a client and server commonly follows a request-response model.

**Request:** The client asks the server for information or an action.

**Response:** The server processes the request and returns a result.

Example:

1. User enters a website address.
2. Browser sends a request to the web server.
3. Server processes the request.
4. Server sends an HTTP response.
5. Browser displays the website.

### Protocol

A protocol is a set of rules that determines how devices communicate.

Examples:

- HTTP.
- HTTPS.
- TCP.
- UDP.
- DNS.
- SSH.
- SMTP.

### Port

A port is a logical communication endpoint used by applications and services.

Port numbers help identify which service should receive network traffic on a host.

Examples:

- HTTP: 80.
- HTTPS: 443.
- SSH: 22.
- DNS: 53.

### DNS

DNS stands for Domain Name System.

It translates domain names into information such as IP addresses so clients can locate network services.

Example:

```text
Domain: example.com
IP:     93.184.216.34
```

The IP shown here is illustrative.

### HTTP and HTTPS

HTTP stands for Hypertext Transfer Protocol.

HTTPS stands for Hypertext Transfer Protocol Secure.

HTTP is a stateless client-server protocol used for communication on the World Wide Web.

Stateless means each HTTP request is handled independently at the protocol level. Websites can maintain sessions using cookies, tokens or other mechanisms.

Common HTTP methods:

| Method  | Purpose                                             |
| ------- | --------------------------------------------------- |
| GET     | Retrieve information                                |
| POST    | Submit data or request processing                   |
| PUT     | Create or replace a resource                        |
| DELETE  | Request deletion of a resource                      |
| PATCH   | Partially update a resource                         |
| HEAD    | Retrieve response headers without the response body |
| OPTIONS | Request supported communication options             |
| CONNECT | Establish a tunnel through a proxy                  |
| TRACE   | Diagnostic request method                           |

HTTP methods and status codes are discussed in the Web section.

## 2.5 Virtualization

Virtualization allows one physical computer to behave like multiple independent computers.

Each virtual computer is called a Virtual Machine (VM).

### Hypervisor

A hypervisor is the software layer that creates and manages virtual machines.

It performs several functions:

- Divides physical hardware resources among virtual machines.
- Allocates CPU, RAM and storage.
- Provides virtual networking.
- Starts and stops virtual machines.
- Pauses and resumes virtual machines.
- Clones virtual machines.
- Maintains isolation between virtual machines.

### Types of Hypervisors

#### Type 1 Hypervisor — Bare Metal

A Type 1 hypervisor runs directly on physical hardware.

Characteristics:

- Does not require a general-purpose host operating system underneath.
- Commonly used in data centers.
- Designed for enterprise virtualization.
- Provides direct management of physical hardware resources.

#### Type 2 Hypervisor — Hosted

A Type 2 hypervisor runs as an application on an existing operating system.

Characteristics:

- Easier to install on a personal computer.
- Useful for learning and testing.
- Runs on top of Windows, Linux or macOS.

Examples:

- Oracle VirtualBox.
- VMware Workstation.

### Virtual Machine

A virtual machine is a software-defined computer created by a hypervisor.

A VM has:

- Virtual CPU.
- Virtual RAM.
- Virtual storage.
- Virtual network interface.
- Guest operating system.
- Applications and settings.

A VM can run operating systems such as Windows and Linux.

VM isolation is useful, but it is not absolute. Host and hypervisor security remain important.

### Containers

A container is a lightweight, isolated environment used to run an application and its dependencies.

Containers:

- Package an application with its required libraries and configuration.
- Share the host operating system's kernel.
- Start quickly.
- Provide process and resource isolation.
- Help applications run consistently across supported environments.

### Docker

Docker is an open-source platform commonly used to build, distribute and run containers.

Important Docker terms:

| Term          | Meaning                                                 |
| ------------- | ------------------------------------------------------- |
| Docker Image  | A packaged template used to create containers           |
| Container     | A running instance of an image                          |
| Docker Engine | Software used to build and run containers               |
| Host          | Machine running the container engine                    |
| Port Mapping  | Makes a container service reachable through a host port |

### Virtual Machine vs. Container

| Virtual Machine                           | Container                                       |
| ----------------------------------------- | ----------------------------------------------- |
| Virtualizes a complete computer           | Isolates application processes                  |
| Runs a guest operating system             | Shares the host kernel                          |
| Generally consumes more resources         | Generally lightweight                           |
| Useful when a separate guest OS is needed | Useful for packaging and deploying applications |

### Important Terminology

- **Virtualization:** Makes one physical computer act like multiple separate computers.
- **Hypervisor:** Software that creates and manages virtual machines.
- **VM:** A virtual computer running on physical hardware.
- **Container:** An isolated environment for an application and its dependencies.
- **Container image:** A template used to create containers.
- **Network port:** A numbered logical communication endpoint.

## 2.6 Cloud Computing Fundamentals

Cloud computing provides computing resources such as servers, storage, networking and databases over a network, commonly the internet.

### Characteristics and Benefits of Cloud Computing

**Scalability:** Resources can be increased or decreased according to application requirements.

**On-demand self-service:** Users can provision computing resources when needed.

**Pay for what you use:** Charges are commonly based on consumed resources and the provider's pricing model.

**High availability:** Cloud services can use redundancy and multiple components or locations to reduce outages.

**Global access:** Applications and services can be made available to users in different geographical regions.

**Provider-managed infrastructure:** Cloud providers manage physical data-center infrastructure, while customers remain responsible for their part of the shared-responsibility model.

Cloud services are not automatically secure. Incorrect permissions, exposed services and insecure configurations can still create security risks.

### Cloud Deployment Models

#### Public Cloud

Cloud services are provided by a cloud provider over shared infrastructure.

Commonly used for:

- Websites.
- Startups.
- Business applications.
- Scalable workloads.

Examples of providers include AWS, Azure and Google Cloud.

#### Private Cloud

Cloud infrastructure is dedicated to one organization.

Commonly used where greater control, customization or specific compliance requirements are needed.

#### Hybrid Cloud

Combines private infrastructure with public-cloud services.

Example:

An organization can keep sensitive information in a private environment while using public cloud resources for applications that require additional scalability.

### Cloud Service Models

#### IaaS — Infrastructure as a Service

The provider supplies basic computing resources such as:

- Virtual servers.
- Storage.
- Networking.
- Virtualization infrastructure.

The customer generally manages:

- Operating system.
- Applications.
- Data.
- Many access and security configurations.

Example: Amazon EC2.

#### PaaS — Platform as a Service

The provider manages the infrastructure, operating system and application platform.

The customer focuses mainly on developing, deploying and maintaining applications and their data.

#### SaaS — Software as a Service

The provider supplies a complete application over a network.

Examples:

- Gmail.
- Microsoft 365.
- Zoom.

### IaaS vs. PaaS vs. SaaS

| Model | Provider Responsibility                      | Customer Focus                          |
| ----- | -------------------------------------------- | --------------------------------------- |
| IaaS  | Physical infrastructure and virtualization   | OS, applications and data               |
| PaaS  | Infrastructure, OS and platform              | Application code and data               |
| SaaS  | Complete application and underlying platform | Users, access and service configuration |

### Cloud Terminology

- **Cloud instance:** A virtual computing resource running in the cloud.
- **Instance type:** Defines the compute, memory, storage and networking capacity of an instance.
- **EC2:** Amazon Elastic Compute Cloud, an AWS service that provides virtual servers.
- **Cloud provider:** A company that offers cloud infrastructure or services.

Examples of providers:

- Amazon Web Services (AWS).
- Microsoft Azure.
- Google Cloud.
- IBM Cloud.
- Oracle Cloud.
- Alibaba Cloud.

# 3. Operating System Basics

An Operating System (OS) is software that manages computer hardware and provides services to applications and users.

It acts as an interface between applications and the physical hardware.

Examples:

- Windows.
- Linux.
- macOS.
- Android.
- iOS.

## 3.1 Kernel Space and User Space

Modern operating systems separate execution into different privilege levels.

### Kernel Space

Kernel space is the highly privileged area where the operating-system kernel runs.

The kernel manages:

- CPU scheduling.
- Memory.
- Device access.
- File systems.
- Core operating-system operations.

### User Space

User space is where normal applications and many system utilities execute.

Examples:

- Web browsers.
- Text editors.
- Media players.
- Office applications.

Applications request operating-system services through system calls instead of directly controlling hardware.

### Kernel Space vs. User Space

| Kernel Space                              | User Space                                                   |
| ----------------------------------------- | ------------------------------------------------------------ |
| Highly privileged                         | Restricted privileges                                        |
| Runs the OS kernel                        | Runs applications and utilities                              |
| Manages system resources                  | Requests OS services                                         |
| Has access to protected system operations | Normally cannot directly access protected hardware resources |

The separation helps limit the damage caused by faulty or malicious applications.

## 3.2 Main Responsibilities of an Operating System

### Process Management

The OS creates, schedules and terminates processes.

A process is an instance of a running program.

Examples:

- Running a browser.
- Running a media player.
- Running an antivirus application.

**PID — Process ID:** A unique identifier assigned to a process by the operating system.

### Memory Management

The OS allocates and manages memory used by applications and processes.

It:

- Allocates memory.
- Tracks memory usage.
- Protects memory spaces.
- Releases memory when it is no longer needed.
- Uses virtual memory mechanisms when necessary.

### File-System Management

The OS organizes files and directories.

It manages:

- File creation.
- File deletion.
- File reading and writing.
- Directory structure.
- File permissions.
- File ownership.

### User Management

The OS maintains user accounts and controls access.

It manages:

- Authentication.
- Permissions.
- User accounts.
- User groups.
- Access to resources.

### Device Management

The OS communicates with hardware through device drivers and system interfaces.

Examples:

- Mouse.
- Keyboard.
- Printer.
- Network adapter.
- External storage.

### Operating System Security

Important operating-system security functions include:

**Authentication:** Verifies the identity of a user through a password, biometrics or another authentication mechanism.

**Permissions:** Controls which users and applications can read, write or execute resources.

**Isolation:** Keeps processes separated and protects the kernel from normal user applications.

**System protection:** Protects critical files and settings from unauthorized changes.

## 3.3 Operating System Interfaces

There are two common ways to interact with an operating system.

### GUI — Graphical User Interface

A GUI allows users to interact with the computer through visual elements.

Examples:

- Windows desktop.
- Application windows.
- Icons.
- Menus.
- Buttons.

### CLI — Command-Line Interface

A CLI allows users to interact with the operating system by entering text commands.

Examples:

- Windows Command Prompt.
- Windows PowerShell.
- Linux Terminal.

| GUI                            | CLI                                           |
| ------------------------------ | --------------------------------------------- |
| Uses graphical elements        | Uses text commands                            |
| Easier for many everyday tasks | Useful for administration and automation      |
| Can require more interaction   | Often efficient for repetitive tasks          |
| Commonly used by general users | Commonly used by administrators and engineers |

## 3.5 Windows Basics and Security

### Windows User Accounts

#### Standard User

A standard user can perform normal activities but has restricted permission to make system-wide changes.

#### Administrator

An administrator has elevated privileges and can:

- Install software.
- Modify protected system settings.
- Manage user accounts.
- Change system configurations.

#### Guest Account

A guest account provides restricted temporary access where this functionality is enabled.

Guest access is often disabled in managed environments.

Windows Settings is the modern interface for managing system configuration.

Examples:

- Accounts.
- Network and Internet.
- Windows Update.
- Devices.
- Privacy and security.
- Personalization.

### Control Panel

### Updating Applications

Applications receive updates to:

- Fix software bugs.
- Improve stability.
- Add features.
- Fix security vulnerabilities.
- Improve performance.

#### Virus & Threat Protection

Provides malware scanning and real-time protection.

#### Firewall & Network Protection

Displays firewall settings and network profiles.

#### App & Browser Control

Provides controls for application and browser security.

#### Device Security

Displays supported device-level security features.

### Windows Defender Firewall

A firewall monitors and controls network traffic based on configured rules.

Windows uses three main network profiles:

| Profile | Purpose                                               |
| ------- | ----------------------------------------------------- |
| Domain  | Used when connected to an organization domain network |
| Private | Used for a trusted network, such as a home network    |

Firewall rules may consider:

- Source IP.
- Destination IP.
- Protocol.
- Port.
- Application.
- Network profile.
- Traffic direction.

Use restrictive rules and allow only the traffic required for legitimate operations.

# 4. Software Basics

Software is a collection of instructions and data that tells a computer how to perform tasks.

Common software categories:

- **System software:** Operating systems, drivers and utilities.
- **Application software:** Browsers, office applications and media players.

### Binary Place Values

Binary uses powers of 2.

```text
Position:  3   2   1   0
Value:     8   4   2   1
```

```text
Binary:    1   0   0   1
Decimal:   8   0   0   1
```

Therefore:

```text
1001₂ = 9₁₀
```

### Binary to Decimal

Multiply each binary digit by its place value and add the results.

Example:

```text
10110₂

= (1 × 16) + (0 × 8) + (1 × 4) + (1 × 2) + (0 × 1)

= 16 + 0 + 4 + 2 + 0

= 22₁₀
```

### Decimal to Binary

Repeatedly divide the decimal number by 2 and record the remainders.

Read the remainders from bottom to top.

Example: Convert 13 to binary.

```text
13 ÷ 2 = 6 remainder 1
 6 ÷ 2 = 3 remainder 0
 3 ÷ 2 = 1 remainder 1
 1 ÷ 2 = 0 remainder 1
```

Result:

```text
13₁₀ = 1101₂
```

| E           |      14 |

Each position represents a power of 16.

Example:

```text

= 36,864 + 2,816 + 208 + 15
```

Each position represents a power of 8.

It is an early character encoding standard using values from 0 to 127.

## 4.3 Unicode

Unicode is a universal character-set standard designed to represent characters from many languages, scripts and symbol systems.

It assigns a unique code point to each character.

Examples:

| Character | Unicode Code Point |
| --------- | ------------------ |
| A         | `U+0041`           |
| Ω         | `U+03A9`           |

A Unicode code point identifies a character. An encoding defines how that code point is represented as bytes.

### UTF-8

Characteristics:

- Uses one to four bytes per Unicode code point.
- Widely used on the web.
- Compatible with ASCII for the basic ASCII range.
- Efficient for many common text workloads.

### UTF-16

UTF-16 encodes Unicode using one or two 16-bit code units.

Some characters outside the Basic Multilingual Plane use a surrogate pair.

### UTF-32

UTF-32 uses a fixed 32-bit code unit for each Unicode code point.

It is straightforward but generally uses more storage for text.

### Unicode vs. UTF-8

| Unicode                                   | UTF-8                                            |
| ----------------------------------------- | ------------------------------------------------ |
| Defines characters and code points        | Defines how Unicode code points are encoded      |
| Provides a universal character repertoire | Uses variable-length byte sequences              |

## 5.1 What Is Networking?

A computer network is a group of connected devices that communicate and share resources.

Examples of shared resources:

- Files.

### Important Networking Terms

## 5.2 IP and MAC Addresses

### IP Address

An IP address is a logical address used to identify an interface on an IP network and help route traffic.

There are two major IP versions.

#### IPv4

- Uses 32 bits.
- Written as four decimal octets.
- Each octet ranges from 0 to 255.

Example:

```text
192.168.1.10
```

#### IPv6

- Uses 128 bits.
- Written in hexadecimal groups separated by colons.

Example:

```text
2001:db8::10
```

### Public IP Address

A public IP address is globally routable address space, subject to routing and provider policies.

It is commonly used for communication across the public internet.

### Private IP Address

Private IP addresses are used inside private networks and are not directly routed across the public internet.

Common private IPv4 ranges:

| Range                 | Private Address Block |
| --------------------- | --------------------- |
| Class A private range | `10.0.0.0/8`          |
| Class B private range | `172.16.0.0/12`       |
| Class C private range | `192.168.0.0/16`      |

### Static IP Address

A static IP address is configured to remain fixed.

Common uses:

- Servers.
- Network devices.
- Infrastructure services.

### Dynamic IP Address

A dynamic IP address is assigned automatically, commonly through DHCP.

### MAC Address

MAC stands for Media Access Control.

A MAC address is a link-layer identifier associated with a network interface.

Ethernet MAC addresses are commonly 48 bits long and written as six hexadecimal pairs.

Example:

```text
00:1A:2B:3C:4D:5E
```

### IP Address vs. MAC Address

| IP Address                           | MAC Address                             |
| ------------------------------------ | --------------------------------------- |
| Logical network-layer address        | Link-layer identifier                   |
| Used for routing between IP networks | Used for delivery on a local link       |
| May change between networks          | Usually assigned to a network interface |
| IPv4 or IPv6                         | Common Ethernet MAC format is 48 bits   |

MAC addresses can be changed or randomized by software in some environments.

## 5.3 LANs and Network Topologies

A LAN connects devices within a limited geographical area.

Examples:

- Home network.
- Office network.
- Campus network.

Common LAN components:

- Switches.
- Routers.
- Wireless access points.
- Firewalls.
- Servers.
- Client devices.

### Network Topology

A network topology describes how network devices are arranged or connected.

#### Star Topology

Devices connect to a central switch or hub.

It is common in modern Ethernet LANs.

#### Bus Topology

Devices share a common communication backbone.

It is mostly associated with older network designs.

#### Ring Topology

Devices form a logical or physical ring.

#### Mesh Topology

Devices have multiple interconnections.

#### Tree Topology

Multiple star networks connect through a hierarchy of network devices.

### Why Topology Matters

Topology affects:

- Network performance.
- Resilience.
- Troubleshooting.
- Scalability.
- Impact of device or link failures.

## 5.4 Subnetting

Subnetting divides a large IP network into smaller logical networks called subnets.

### Why Subnetting Is Important

- Organizes devices by location or department.
- Reduces broadcast domains in IPv4 networks.
- Improves network management.
- Allows different access-control policies.
- Uses address space efficiently.
- Helps separate systems according to business function.

### Subnet Mask

An IPv4 subnet mask identifies which bits represent the network portion and which bits represent the host portion.

Example:

```text
IP Address:  192.168.1.10
Subnet Mask: 255.255.255.0
CIDR:        /24
```

### CIDR Notation

CIDR stands for Classless Inter-Domain Routing.

It uses a slash followed by the number of network bits.

Example:

```text
192.168.1.0/24
```

The `/24` indicates that the first 24 bits represent the network prefix.

### Important Subnetting Terms

**Network Address:** Identifies the subnet.

**Broadcast Address:** In an IPv4 broadcast subnet, addresses all hosts on that subnet.

**Usable Host Range:** Addresses that can generally be assigned to devices in a conventional IPv4 subnet.

**Default Gateway:** The router address a host uses to reach networks outside its local subnet.

### Example: /24 Network

```text
Network:          192.168.1.0/24
Subnet Mask:      255.255.255.0
Network Address:  192.168.1.0
First Host:       192.168.1.1
Last Host:        192.168.1.254
Broadcast:        192.168.1.255
```

A conventional `/24` IPv4 subnet contains 256 total addresses, of which 254 are usable host addresses.

## 5.5 Ping and ICMP

ICMP stands for Internet Control Message Protocol.

It is used by network devices to exchange control and diagnostic messages.

### Ping

`ping` commonly sends ICMP Echo Request messages and checks whether Echo Reply messages are received.

Example:

```bash
ping 192.0.2.10
```

Ping helps identify:

- Basic network reachability.
- Packet loss.
- Round-trip time.
- Possible latency problems.

### Important Limitations

- Successful ping does not prove that a particular application is working.
- Successful ping does not prove that a specific TCP port is open.
- Failed ping does not always mean the host is down.
- A firewall may block ICMP traffic.

## 5.6 ARP and DHCP

### ARP — Address Resolution Protocol

ARP helps an IPv4 device discover the MAC address associated with a local IPv4 address.

Example:

A device wants to communicate with another device on the same local IPv4 network.

It knows the destination IP address but needs the destination MAC address for local Ethernet delivery.

### ARP Process

1. Host checks its ARP cache.
2. If no mapping exists, it sends an ARP request.
3. The request is broadcast on the local network.
4. The device using the requested IP address responds with its MAC address.
5. The mapping is stored in the ARP cache for a period of time.

IPv6 uses Neighbor Discovery Protocol (NDP) instead of ARP.

### DHCP — Dynamic Host Configuration Protocol

DHCP automatically provides network configuration to clients.

A DHCP server can assign:

- IP address.
- Subnet mask or prefix information.
- Default gateway.
- DNS server addresses.
- Lease duration.
- Other network configuration options.

### DHCP DORA Process

DORA represents the four common stages of an IPv4 DHCP exchange.

#### 1. Discover

Client searches for available DHCP servers.

#### 2. Offer

DHCP server offers an IP address and configuration.

#### 3. Request

Client requests the offered configuration.

#### 4. Acknowledge

Server confirms the lease and configuration.

```text
Client
  |
  | DHCP Discover
  v
DHCP Server
  |
  | DHCP Offer
  v
Client
  |
  | DHCP Request
  v
DHCP Server
  |
  | DHCP Acknowledgement
  v
Client receives configuration
```

A DHCP lease is time-limited and may be renewed.

## 5.7 OSI and TCP/IP Models

Network models help explain how data moves through different layers of communication.

### OSI Model

OSI stands for Open Systems Interconnection.

It contains seven layers.

| Layer | Name         | Responsibility                                        | Examples                            |
| ----: | ------------ | ----------------------------------------------------- | ----------------------------------- |
|     7 | Application  | Network services used by applications                 | HTTP, DNS, SMTP                     |
|     6 | Presentation | Data representation, encoding and encryption concepts | Character encoding, data formats    |
|     5 | Session      | Establishes and manages communication sessions        | Session management                  |
|     4 | Transport    | End-to-end transport and ports                        | TCP, UDP                            |
|     3 | Network      | Logical addressing and routing                        | IP, routers                         |
|     2 | Data Link    | Local-link delivery and framing                       | Ethernet, MAC addresses, switches   |
|     1 | Physical     | Transmission of raw bits                              | Copper cables, fiber, radio signals |

### OSI Layer Explanation

#### Layer 7 — Application

Provides network services that applications use.

Examples:

- HTTP.
- HTTPS.
- DNS.
- SMTP.
- FTP.

#### Layer 6 — Presentation

Deals with data representation and transformation concepts.

Examples:

- Character encoding.
- Data formatting.
- Encryption and decryption concepts.

#### Layer 5 — Session

Deals with establishing, managing and terminating communication sessions.

#### Layer 4 — Transport

Provides communication between processes.

Important protocols:

- TCP.
- UDP.

#### Layer 3 — Network

Handles logical addressing and routing.

Example:

- IPv4.
- IPv6.

#### Layer 2 — Data Link

Handles local network delivery and framing.

Examples:

- Ethernet.
- MAC addresses.
- Switches.

#### Layer 1 — Physical

Deals with physical transmission of bits.

Examples:

- Network cables.
- Fiber-optic cables.
- Radio signals.

### TCP/IP Model

A common TCP/IP model contains four layers.

| TCP/IP Layer          | Responsibility                                        | Examples             |
| --------------------- | ----------------------------------------------------- | -------------------- |
| Application           | Application protocols and formats                     | HTTP, DNS, SMTP, SSH |
| Transport             | End-to-end communication                              | TCP, UDP             |
| Internet              | IP addressing and routing                             | IPv4, IPv6, ICMP     |
| Link / Network Access | Local network communication and physical transmission | Ethernet, Wi-Fi      |

### OSI vs. TCP/IP Model

The OSI model contains seven layers, while the common TCP/IP model contains four layers.

Both models help explain how network communication works.

## 5.8 Packets, Frames, Ports and Protocols

### Frame

A frame is a data unit at the Data Link layer.

An Ethernet frame commonly contains:

- Source MAC address.
- Destination MAC address.
- Type or length information.
- Payload.
- Frame check sequence.

### Packet

A packet is a data unit at the Network layer.

An IP packet includes:

- Source IP address.
- Destination IP address.
- Other IP header fields.
- Payload.

### Segment

A segment commonly refers to a TCP transport-layer data unit.

UDP commonly uses the term datagram.

### Encapsulation

Encapsulation occurs when each network layer adds the information required for its communication function.

Simplified view:

```text
Application Data
       |
       v
Transport Header + Data
       |
       v
IP Header + Transport Data
       |
       v
Ethernet Header + IP Packet
       |
       v
Physical Transmission
```

At the receiving end, the corresponding layers process the data and remove their headers.

### Port Numbers

A port number identifies a service endpoint on a host.

TCP and UDP each have their own port-number space.

Common port numbers:

|  Port | Service | Protocol                           |
| ----: | ------- | ---------------------------------- |
| 20/21 | FTP     | TCP                                |
|    22 | SSH     | TCP                                |
|    23 | Telnet  | TCP                                |
|    25 | SMTP    | TCP                                |
|    53 | DNS     | UDP/TCP                            |
| 67/68 | DHCP    | UDP                                |
|    80 | HTTP    | TCP                                |
|   110 | POP3    | TCP                                |
|   123 | NTP     | UDP                                |
|   143 | IMAP    | TCP                                |
|   443 | HTTPS   | TCP; HTTP/3 uses QUIC over UDP     |
|  3389 | RDP     | TCP/UDP depending on configuration |

Port numbers are conventions. A service may be configured to use a different port.

### TCP vs. UDP

#### TCP — Transmission Control Protocol

Characteristics:

- Connection-oriented.
- Provides reliable and ordered delivery mechanisms.
- Uses acknowledgements.
- Supports retransmission.
- Uses flow and congestion control mechanisms.

Commonly used for:

- Web traffic over HTTP/1.1 and HTTP/2.
- SSH.
- Email protocols.
- Many file-transfer services.

#### UDP — User Datagram Protocol

Characteristics:

- Connectionless.
- Does not provide TCP-style delivery guarantees.
- Has lower protocol overhead.
- Useful when low latency is important.

Commonly used for:

- DNS queries.
- Voice communication.
- Streaming.
- Online gaming.
- Other latency-sensitive communications.

### TCP vs. UDP Comparison

| TCP                                      | UDP                                   |
| ---------------------------------------- | ------------------------------------- |
| Connection-oriented                      | Connectionless                        |
| Reliable and ordered delivery mechanisms | No TCP-style delivery guarantee       |
| Acknowledgements and retransmissions     | No built-in TCP-style acknowledgement |
| More protocol overhead                   | Lower protocol overhead               |

## 5.9 Network Devices

### Switch

A switch connects devices within a LAN and forwards Ethernet frames based on MAC-address learning.

### Router

A router connects different IP networks and forwards packets based on routing information.

### Wireless Access Point

An access point allows wireless devices to connect to a network.

### Firewall

A firewall enforces network traffic rules and helps protect systems from unauthorized communication.

### Modem / ONT

A modem or Optical Network Terminal terminates or converts the access technology used by an internet provider.

### Network Interface Card

A NIC provides wired or wireless network connectivity to a device.

### Load Balancer

A load balancer distributes client requests across multiple servers or service instances.

### Proxy

A proxy acts as an intermediary between a client and a server.

### Switch vs. Router

| Switch                                | Router                                |
| ------------------------------------- | ------------------------------------- |
| Connects devices in a LAN             | Connects different IP networks        |
| Commonly forwards using MAC addresses | Forwards using IP routing information |
| Primarily associated with Layer 2     | Primarily associated with Layer 3     |

## 5.10 Port Forwarding, Firewalls and VPNs

### Port Forwarding

Port forwarding is a router or firewall configuration that forwards traffic arriving at an external address and port to a specified internal host and port.

Example:

```text
Internet Client
      |
      | Public IP:443
      v
Edge Router / Firewall
      |
      | Forward to 10.0.0.20:443
      v
Internal Web Server
```

Port forwarding can make an internal service reachable from outside the network.

Incorrect or unnecessary forwarding can expose internal services.

Security best practices:

- Forward only required ports.
- Restrict permitted source addresses where possible.
- Avoid exposing administrative services unnecessarily.
- Review forwarding rules regularly.
- Monitor exposed services.

### Firewall

A firewall monitors and controls network traffic based on defined security rules.

Common types:

#### Host-Based Firewall

Runs on an individual endpoint or server.

#### Network-Based Firewall

Protects a network boundary or segment.

#### Next-Generation Firewall

May combine traditional traffic filtering with application awareness and additional inspection capabilities.

Firewall rules commonly consider:

- Source IP.
- Destination IP.
- Source and destination ports.
- Protocol.
- Interface.
- Traffic direction.
- Connection state.

A strong firewall policy follows the principle of least privilege.

### VPN — Virtual Private Network

A VPN creates a protected communication tunnel over an untrusted or shared network.

Common uses:

- Secure remote access.
- Connecting branch offices.
- Accessing internal corporate applications.
- Secure administration.

A VPN can provide confidentiality and integrity through encryption and authentication, depending on the protocol and configuration.

A VPN does not automatically make a compromised endpoint safe.

## 5.11 NOC Operations and Security Relevance

NOC stands for Network Operations Center.

A NOC monitors and maintains network availability and performance.

NOC activities are closely related to security because network failures, misconfigurations and unusual traffic can affect confidentiality, integrity and availability.

### Common NOC Activities

- Monitor network devices.
- Monitor WAN and LAN connectivity.
- Investigate high latency.
- Investigate packet loss.
- Monitor interface errors.
- Check routing and switching.
- Troubleshoot DNS and DHCP.
- Manage approved firewall changes.
- Maintain network documentation.
- Coordinate with service providers.
- Escalate incidents to appropriate teams.

### Configuration Management

Configuration management keeps device settings controlled, documented and recoverable.

Good practices:

1. Record the business reason for a change.
2. Define the change scope.
3. Obtain required approval.
4. Back up the current configuration.
5. Implement during the approved window.
6. Validate services and connectivity.
7. Document the outcome.
8. Roll back when required by the approved procedure.

### Virtualization in NOC Operations

Virtualization is used to:

- Provision servers.
- Test changes.
- Consolidate workloads.
- Recover services.
- Create isolated test environments.

Infrastructure teams may monitor:

- VM availability.
- CPU utilization.
- Memory utilization.
- Storage capacity.
- Virtual switches.
- Network connectivity.

### LAN Segmentation

LAN segmentation divides a network into smaller logical areas.

Benefits:

- Better management.
- Reduced unnecessary traffic.
- Improved access control.
- Reduced scope of some security incidents.

Common segmentation methods:

#### VLAN

A VLAN creates a separate Layer 2 broadcast domain on compatible switching infrastructure.

#### Subnet

A subnet creates a separate logical IP network.

#### ACL and Firewall Rules

These restrict communication between network segments.

#### Role-Based Segmentation

Devices can be separated according to their function.

Example:

```text
Corporate LAN
  |
  |-- User VLAN
  |-- Server VLAN
  |-- Guest Wi-Fi VLAN
  |-- Voice VLAN
  |-- Network Management VLAN
```

Segmentation is effective only when routing and access-control rules are configured correctly.

### Data Wiping and Asset Decommissioning

When computers, storage devices or network equipment are retired, organizational information must be handled according to approved data-retention and sanitization procedures.

A controlled process may include:

1. Confirm asset ownership and authorization.
2. Identify the storage media.
3. Check retention and legal-hold requirements.
4. Select an approved sanitization method.
5. Verify the result where applicable.
6. Record asset details and sanitization results.
7. Dispose of or reuse the device through the approved process.

Simply deleting files or formatting a drive may not securely erase the underlying data.

### NOC vs. SOC

| NOC                                       | SOC                                                      |
| ----------------------------------------- | -------------------------------------------------------- |
| Focuses on availability and performance   | Focuses on security monitoring and incident response     |
| Investigates outages and network failures | Investigates threats and suspicious activity             |
| Uses network monitoring tools             | Uses SIEM, EDR and security tools                        |
| Maintains network connectivity            | Protects systems and information                         |
| Supports network changes and recovery     | Detects, investigates and coordinates security incidents |

NOC and SOC teams often collaborate during security incidents.

Example:

1. SOC detects suspicious traffic from an endpoint.
2. SOC requests network information or containment support.
3. NOC identifies the device, VLAN and network path.
4. An authorized team applies the required network restriction.
5. Both teams validate the action and document the incident.

# 6. How the Web Works

The web uses clients, servers, DNS, IP networking and application protocols to deliver information and services.

## 6.1 DNS and Domain Hierarchy

DNS stands for Domain Name System.

It translates domain names into records that clients can use, such as IP addresses.

People remember domain names more easily than numeric IP addresses.

Example:

```text
www.example.com
```

### Domain Hierarchy

Domain names are organized into levels, read from right to left.

Example:

```text
www.example.com
```

- `.com` — Top-Level Domain (TLD).
- `example` — Second-level domain.
- `www` — Subdomain.

### DNS Server Roles

#### DNS Resolver

A recursive resolver receives a client's query and obtains an answer through its cache or by querying other DNS servers.

#### Root DNS Server

Directs the resolver toward the appropriate TLD name servers.

#### TLD DNS Server

Directs the resolver toward the authoritative name servers for a domain.

#### Authoritative DNS Server

Holds DNS records for a domain's zone and provides authoritative answers.

## 6.2 DNS Record Types

| Record | Purpose                                          | Example                                     |
| ------ | ------------------------------------------------ | ------------------------------------------- |
| A      | Maps a domain to an IPv4 address                 | `example.com` to an IPv4 address            |
| AAAA   | Maps a domain to an IPv6 address                 | `example.com` to an IPv6 address            |
| CNAME  | Creates an alias to another canonical name       | `shop.example.com` aliases another hostname |
| MX     | Identifies mail servers for a domain             | Email delivery                              |
| TXT    | Stores text information associated with a domain | Domain verification and email policies      |
| NS     | Identifies authoritative name servers            | DNS delegation                              |
| SOA    | Contains zone administration information         | DNS zone metadata                           |
| PTR    | Supports reverse DNS lookup                      | IP address to hostname                      |
| SRV    | Specifies service location information           | Service discovery                           |

### TTL — Time to Live

TTL specifies how long a DNS record can remain in a cache before it should be refreshed.

TTL values are generally measured in seconds.

Caching reduces repeated queries and improves performance.

DNS changes may not become visible everywhere immediately because cached records may remain until their TTL expires.

## 6.3 DNS Resolution Process

A typical DNS lookup follows these stages when the answer is not already cached.

1. **Local cache check:** The operating system checks whether it already has a valid DNS answer.
2. **Recursive resolver query:** The client sends a request to its recursive DNS resolver.
3. **Resolver cache check:** The recursive resolver checks its own cache.
4. **Root referral:** If needed, the resolver asks a root DNS server which directs it to the appropriate TLD servers.
5. **TLD referral:** The TLD server identifies the authoritative name servers.
6. **Authoritative answer:** The resolver queries an authoritative DNS server for the requested record.
7. **Caching and response:** The resolver caches the answer according to its TTL and returns it to the client.
8. **Connection:** The client uses the returned address to connect to the destination service.

### DNS Resolution Flow

```text
User enters domain
        |
        v
Local DNS Cache Check
        |
        v
Recursive DNS Resolver
        |
        v
Root DNS Server
        |
        v
TLD DNS Server
        |
        v
Authoritative DNS Server
        |
        v
IP Address Returned
        |
        v
Client Connects to Server
```

Some lookups require fewer steps because answers are already cached.

DNS can use both UDP and TCP depending on the query, response size and circumstances.

## 6.4 HTTP, HTTPS and URLs

### HTTP

HTTP stands for Hypertext Transfer Protocol.

It is an application-layer protocol used for communication between clients and web servers.

HTTP is stateless at the protocol level.

Each request is processed independently, although applications can maintain user sessions using cookies, tokens or server-side session data.

### HTTPS

HTTPS stands for Hypertext Transfer Protocol Secure.

It is HTTP protected by TLS (Transport Layer Security).

TLS helps provide:

**Confidentiality:** Protects data in transit from unauthorized reading.

**Integrity:** Helps detect unauthorized modification of transmitted data.

**Authentication:** Allows the client to validate the server's identity through its certificate and trusted certificate chain.

HTTPS does not guarantee that a website is safe. A malicious website can also use HTTPS.

### URL Structure

Example:

```text
https://www.example.com:443/products?id=25#details
```

| Component | Example           | Meaning                                    |
| --------- | ----------------- | ------------------------------------------ |
| Scheme    | `https`           | Protocol or access method                  |
| Host      | `www.example.com` | Server hostname                            |
| Port      | `443`             | Destination service port                   |
| Path      | `/products`       | Requested resource path                    |
| Query     | `?id=25`          | Additional parameters                      |
| Fragment  | `#details`        | Reference to a section within the resource |

### Common Default Ports

| Protocol | Default Port |
| -------- | -----------: |
| HTTP     |           80 |
| HTTPS    |          443 |

A service can be configured to use different ports.

### Cookies

A cookie is a small piece of data stored by a browser for a website.

- Login sessions.
- User preferences.
- Shopping carts.
- Analytics.
- Application state.

### Important Cookie Attributes

**Secure:** Cookie is sent only over secure connections.

## 6.7 How Websites Work

Most websites contain two broad components:

### Front End — Client Side

The front end is the part of a website that runs in or is rendered by a user's browser.

#### HTML

HyperText Markup Language defines the structure and content of a page.

#### CSS

Cascading Style Sheets control layout, styling and appearance.

#### JavaScript

JavaScript adds interactivity and behavior.

### Back End — Server Side

The back end processes requests, performs application logic, interacts with databases and returns responses.

Typical components:

- Web server.
- Application server.
- Application code.
- Database.
- Authentication services.
- Logging and monitoring services.

### Website Request Flow

1. Browser sends a request.
2. Web server or application receives the request.
3. Application validates the request.
4. Access permissions are checked.
5. Application processes the required business logic.
6. Data is accessed or updated if necessary.
7. Server returns a response.
8. Browser renders the page or updates its content.

## 6.8 HTML Injection

HTML injection occurs when an application includes untrusted input in an HTML page in a way that allows the input to be interpreted as markup rather than ordinary text.

### Possible Causes

- Displaying user input without appropriate output encoding.
- Building HTML through unsafe string concatenation.
- Trusting client-side validation without server-side validation.

### Possible Impact

- Unexpected changes to page content.
- Modification of page layout.
- Display of attacker-controlled HTML.
- In some circumstances, more serious browser-side injection issues.

### Defensive Practices

- Validate input on the server side.
- Apply context-appropriate output encoding.
- Sanitize HTML when restricted HTML input is intentionally supported.
- Use secure templating mechanisms.
- Apply a suitable Content Security Policy (CSP).
- Test input handling through authorized security assessments.

**Important distinction:**

Input validation checks whether data is acceptable.

Output encoding ensures that data is interpreted safely in the context where it is displayed.

Both are important but solve different problems.

# 7. Attacks and Defenses

## 7.1 The CIA Triad

The CIA triad is one of the foundational information-security models.

CIA stands for:

- Confidentiality.
- Integrity.
- Availability.

### Confidentiality

Confidentiality ensures that information is accessible only to authorized people, systems or processes.

Examples of security controls:

- Authentication.
- Access control.
- Encryption.
- Least privilege.
- Data classification.

Example:

An unauthorized person accessing payroll information violates confidentiality.

### Integrity

Integrity ensures that information remains accurate, complete and protected from unauthorized modification.

Examples of security controls:

- File integrity monitoring.
- Hashing.
- Digital signatures.
- Access controls.
- Auditing.
- Protected logs.

Example:

An attacker changes a bank transfer amount without authorization.

This violates integrity.

### Availability

Availability ensures that systems and information are accessible when authorized users need them.

Examples of security controls:

- Backups.
- Redundancy.
- Failover.
- Capacity monitoring.
- Disaster recovery.
- Denial-of-service protection.

Example:

A denial-of-service attack makes a website unavailable.

This violates availability.

### CIA Triad Summary

| Security Property | Main Objective                    | Example Violation        |
| ----------------- | --------------------------------- | ------------------------ |
| Confidentiality   | Prevent unauthorized disclosure   | Data theft               |
| Integrity         | Prevent unauthorized modification | Data tampering           |
| Availability      | Maintain access to services       | Denial-of-service attack |

An incident can affect more than one CIA property simultaneously.

## 7.2 Cryptography Concepts

Cryptography uses mathematical techniques to protect information and support secure communication.

### Plaintext

Readable or original information before encryption.

### Ciphertext

Data after encryption.

### Encryption

The process of converting plaintext into ciphertext.

### Decryption

The process of converting ciphertext back into plaintext.

### Encryption Algorithm

A defined mathematical procedure used to perform encryption and decryption.

### Cryptographic Key

A value used by the cryptographic algorithm to control the operation.

### Basic Encryption Process

```text
Plaintext
    |
    v
Encryption Algorithm + Key
    |
    v
Ciphertext
```

### Basic Decryption Process

```text
Ciphertext
    |
    v
Decryption Algorithm + Key
    |
    v
Plaintext
```

A secure cryptographic system should use sound algorithms and appropriate key management.

Security should not depend on keeping the encryption algorithm secret.

## 7.3 Symmetric Encryption and AES

Symmetric encryption uses the same secret key for encryption and decryption.

### How Symmetric Encryption Works

```text
Plaintext
    |
    v
Encryption using Secret Key
    |
    v
Ciphertext
    |
    v
Decryption using Same Secret Key
    |
    v
Plaintext
```

### Advantages

- Efficient for large amounts of data.
- Generally faster than public-key cryptography.
- Commonly used for storage and network-session encryption.

### Main Challenge

The communicating parties must securely obtain the same secret key.

If an attacker obtains the key, they may be able to decrypt protected data.

### AES — Advanced Encryption Standard

AES is a widely used symmetric block cipher.

AES supports key sizes of:

- 128 bits.
- 192 bits.
- 256 bits.

It is used in many security systems, including storage encryption and secure communication protocols.

Its security depends on correct implementation, appropriate operating modes and secure key management.

### Caesar Cipher

The Caesar cipher is a simple historical substitution cipher.

It shifts each letter by a fixed number of positions in the alphabet.

Example using a shift of 3:

```text
A -> D
B -> E
C -> F
D -> G
...
X -> A
Y -> B
Z -> C
```

It wraps around after Z.

The Caesar cipher is not secure by modern standards because its small key space makes it easy to break.

It is useful for understanding the basic idea of encryption, but not for protecting real information.

## 7.4 Asymmetric Encryption

Asymmetric encryption uses a mathematically related pair of keys:

- Public key.
- Private key.

### Public Key

A public key can be shared with other people or systems.

### Private Key

A private key must be protected and kept secret by its owner.

The two keys are mathematically related, but secure systems make it computationally infeasible to derive the private key from the public key.

### Encryption Using Public and Private Keys

For encryption to a recipient:

1. The sender obtains the recipient's public key.
2. The sender encrypts data for that recipient.
3. The recipient uses the corresponding private key to decrypt the data.

### Digital Signatures

Digital signatures use a private key to sign data.

The corresponding public key is used to verify the signature.

They help establish:

- Authenticity.
- Integrity.
- Evidence that the signature corresponds to the private key.

### Symmetric vs. Asymmetric Encryption

| Symmetric Encryption                    | Asymmetric Encryption                         |
| --------------------------------------- | --------------------------------------------- |
| Uses one shared secret key              | Uses a public/private key pair                |
| Efficient for large amounts of data     | Usually more computationally expensive        |
| Requires secure secret-key distribution | Supports authentication and key establishment |
| Example: AES                            | Examples: RSA and elliptic-curve cryptography |

## 7.5 Certificates and HTTPS

A digital certificate binds a public key to an identity according to the certificate contents and validation process.

A typical TLS server certificate includes:

- Domain identity.
- Public key.
- Issuer information.
- Validity period.
- Extensions and permitted uses.
- Digital signature from the issuer.

### Certificate Authority (CA)

A Certificate Authority is an entity trusted to issue or sign certificates under a trust system.

Browsers and operating systems maintain trust stores containing trusted certificate authorities.

### Simplified HTTPS/TLS Connection

1. Browser connects to the website's server.
2. Server presents its certificate and handshake information.
3. Browser checks the certificate chain and validity.
4. Browser checks whether the certificate name matches the requested website.
5. The parties negotiate cryptographic settings and establish shared session keys.
6. Symmetric encryption protects application data exchanged during the session.

### Why Does HTTPS Use Both Symmetric and Asymmetric Cryptography?

Asymmetric cryptography helps authenticate the server and establish or protect key material.

Symmetric cryptography efficiently encrypts the large volume of data exchanged during the session.

Modern TLS commonly uses ephemeral key agreement to support forward secrecy.

### HTTPS Security Benefits

- Confidentiality.
- Integrity.
- Server authentication.
- Protection against many forms of network interception and tampering.

HTTPS does not prove that a website is legitimate or harmless. A malicious website can also have a valid HTTPS certificate.

# 8. Become a Hacker — Offensive Security

Offensive security proactively tests systems using authorized attacker techniques to identify weaknesses before malicious attackers exploit them.

The purpose is to discover security gaps, validate their potential impact and recommend remediation.

**All offensive-security testing must be performed within explicit authorization and the defined scope.**

## 8.1 Important Offensive-Security Terms

| Term               | Meaning                                                            |
| ------------------ | ------------------------------------------------------------------ |
| Scope              | Systems and activities permitted during an assessment              |
| Vulnerability      | Weakness in software, hardware, process or configuration           |
| Exploit            | Technique or code that takes advantage of a vulnerability          |
| Enumeration        | Systematically collecting details about hosts, services or users   |
| Credentials        | Authentication information such as usernames, passwords or keys    |
| Authentication     | Verifying identity                                                 |
| Dictionary attack  | Attempts using guesses from a predefined wordlist                  |
| Brute-force attack | Systematically attempts possible combinations                      |
| Red Team           | Team simulating adversary behavior to test organizational defenses |
| Penetration Test   | Authorized assessment of security weaknesses                       |

## 8.2 Red Teaming

Red teaming is a structured exercise that simulates realistic adversary activity against an organization.

It can evaluate:

- Security controls.
- Monitoring.
- Detection capabilities.
- Incident response.
- People and processes.
- Technical infrastructure.

A red-team exercise must have:

- Clear objectives.
- Defined scope.
- Rules of engagement.
- Approved techniques.
- Communication procedures.
- Stop conditions.

## 8.3 Penetration Testing

Penetration testing is an authorized assessment in which testers identify and, where permitted, validate security weaknesses.

### Typical Penetration-Testing Process

1. Confirm authorization and scope.
2. Gather permitted information.
3. Identify exposed services.
4. Discover potential weaknesses.
5. Validate selected findings safely.
6. Document evidence and business impact.
7. Recommend remediation.
8. Retest after fixes.

## 8.4 Tools Mentioned in Pre-Security

### DirBuster

A web directory and file discovery tool used to identify potentially unlinked content on a web server.

### Gobuster

A command-line tool commonly used for:

- Directory discovery.
- File discovery.
- DNS enumeration.
- Other authorized content-discovery tasks.

It can use wordlists to test candidate names.

### Hydra

Hydra is a password-testing tool that automates authentication attempts against supported services.

It can be used during authorized password audits.

Repeated authentication attempts can:

- Lock accounts.
- Trigger security alerts.
- Disrupt services.
- Violate security policies.

It must be used only within an approved test scope.

## 8.5 Responsible Use of Offensive-Security Tools

- Never test systems without permission.
- Stay within the approved target scope.
- Use approved test accounts where possible.
- Respect rate limits and service availability.
- Stop when testing creates unacceptable operational risk.
- Preserve evidence.
- Document findings.
- Report vulnerabilities responsibly.

A tool finding is not automatically a confirmed vulnerability. Results must be verified and assessed.

# 9. Become a Defender — Defensive Security

Defensive security focuses on protecting systems, infrastructure, users and information.

The objective is to prevent attacks, detect suspicious activity, investigate incidents, reduce their impact and improve security.

## 9.1 Blue Team

A Blue Team consists of security professionals responsible for defending an organization's systems and responding to cyber threats.

Common Blue Team responsibilities:

- Monitor alerts.
- Investigate suspicious activity.
- Review security logs.
- Detect malware.
- Identify unauthorized access.
- Coordinate incident response.
- Improve security controls.

## 9.2 Defensive Security Questions

| Question                             | Security Meaning                          | Example                       |
| ------------------------------------ | ----------------------------------------- | ----------------------------- |
| What are you protecting?             | Identify systems and assets               | Asset inventory               |
| Can you see what you are protecting? | Establish visibility                      | Log collection and monitoring |
| What identifies suspicious activity? | Define detection logic                    | Unusual login activity        |
| How do you limit a threat?           | Apply preventive and containment controls | Endpoint isolation            |

## 9.3 Defensive Security Activities

### 1. Prevention

Prevention reduces the likelihood of an attack.

Examples:

- Firewalls.
- Antivirus and endpoint protection.
- Regular patching.
- Secure configuration.
- Multi-factor authentication.
- Least-privilege access.
- User security awareness.

### 2. Detection

Detection identifies suspicious or malicious activity.

Examples:

- Monitoring failed login attempts.
- Detecting unusual processes.
- Reviewing firewall logs.
- Monitoring endpoint alerts.
- Identifying abnormal network traffic.
- Detecting unauthorized changes.

### 3. Mitigation and Containment

Mitigation reduces the impact of a threat.

Containment prevents an incident from spreading while it is investigated.

Examples:

- Isolating a compromised endpoint.
- Disabling a compromised account.
- Blocking malicious network traffic.
- Revoking compromised credentials or tokens.
- Restricting unauthorized access.

Containment actions should follow organizational authorization and incident procedures.

### 4. Analysis and Investigation

Security analysts investigate incidents to understand:

- What happened?
- When did it happen?
- Which systems were affected?
- Which users were involved?
- How did the attack occur?
- Is the threat still active?
- What evidence supports the conclusion?

Common evidence:

- Authentication logs.
- Endpoint logs.
- Firewall logs.
- Network traffic.
- DNS logs.
- Proxy logs.
- File timestamps.
- User and asset records.

Analysts should build timelines, correlate evidence and distinguish confirmed facts from assumptions.

### 5. Response, Recovery and Improvement

After containment and investigation, teams work to remove the cause, restore affected systems and improve security controls.

Examples:

- Remove malicious files.
- Remove persistence mechanisms.
- Reset credentials.
- Revoke compromised tokens.
- Restore systems from trusted backups.
- Patch the exploited weakness.
- Update detection rules.
- Document lessons learned.

## 9.4 Core Defender Principles

### Threat Anticipation

Understand what attackers may target and how they could reach important assets.

### Attack Awareness

Recognize that attacks commonly involve multiple stages.

Defenders should correlate activity instead of evaluating every alert in isolation.

### Risk Prioritization

Prioritize systems based on:

- Business importance.
- Data sensitivity.
- External exposure.
- Vulnerability severity.
- Exploitability.
- Potential impact.

### Continuous Adaptation

Threats, technologies and business requirements change.

Security controls must be reviewed and improved continuously.

## 9.5 Infrastructure Components, Risks and Defenses

| Component         | Potential Risk                           | Defensive Controls                                        |
| ----------------- | ---------------------------------------- | --------------------------------------------------------- |
| Employee devices  | Malware or phishing                      | Endpoint protection, patching, least privilege            |
| Web servers       | Exploitation of exposed services         | Secure configuration, patching, monitoring                |
| Mail servers      | Malicious or deceptive email             | Spam filtering, attachment scanning, email authentication |
| Firewalls         | Incorrect security rules                 | Rule reviews, change control, logging                     |
| Network boundary  | Unauthorized external access             | Restrictive inbound access, network monitoring            |
| Identity platform | Account compromise                       | MFA, access reviews, authentication monitoring            |
| Database          | Unauthorized data access or modification | Access controls, encryption, audit logging                |

## 9.6 Security Operations Center (SOC)

A SOC monitors systems and networks, investigates security alerts and coordinates response actions.

Common SOC responsibilities:

- Monitor SIEM alerts.
- Investigate endpoint alerts.
- Review authentication events.
- Analyze firewall and proxy logs.
- Identify suspicious IP addresses and domains.
- Correlate evidence.
- Prioritize incidents.
- Escalate confirmed or high-risk activity.
- Document investigations.

### SOC Alert Investigation — Basic Process

1. Receive the alert.
2. Check alert details.
3. Identify the affected user or asset.
4. Review relevant timestamps.
5. Collect supporting logs.
6. Correlate related events.
7. Determine whether the activity is benign, suspicious or malicious.
8. Assess potential impact.
9. Escalate or respond according to procedures.
10. Document the investigation.

## 9.7 Threat Intelligence

Threat intelligence research helps organizations understand:

- Threat actors.
- Attack techniques.
- Malicious infrastructure.
- Malware.
- Indicators of compromise.
- Emerging threats.

It helps security teams improve detection and prevention decisions.

## 9.8 Digital Forensics and Incident Response (DFIR)

DFIR combines digital forensics and incident response.

### Digital Forensics

Digital forensics involves identifying, preserving, examining and analyzing digital evidence.

### Incident Response

Incident response is the organized process of handling security incidents.

Common activities:

- Preparation.
- Detection and analysis.
- Containment.
- Eradication.
- Recovery.
- Lessons learned.

## 9.9 NOC and SOC Collaboration

NOC and SOC teams often work together during security incidents.

Example:

1. SOC identifies suspicious network activity from an endpoint.
2. SOC requests network information or containment support.
3. NOC identifies the device, VLAN and network path.
4. An authorized team applies an approved network restriction.
5. Both teams verify the result.
6. The incident and actions are documented.

Clear communication, accurate timestamps, escalation and change records are important.
